## 10.1 Abstract Data Types: Stacks (LIFO) and Queues (FIFO)

An **Abstract Data Type (ADT)** is a mathematical model for data types where the type is defined by its behavior (semantics) from the point of view of a user of the data, specifically in terms of possible values, possible operations on data of this type, and the behavior of these operations.

In linear computing, two complementary ADTs govern sequential processing:

```
+---------------------------------------------------------------------------------+
| Dimension           | Stack (LIFO)                      | Queue (FIFO)          |
+---------------------------------------------------------------------------------+
| Access Paradigm     | Last-In, First-Out                | First-In, First-Out   |
| Primary Operations  | push(x), pop(), top() / peek()    | enqueue(x), dequeue() |
| Algorithmic Essence | Temporal Reversal & Nested State  | Fairness & Temporal Ordering|
| Classic Usages      | Function Calls, Parsers, Undo     | Task Scheduling, BFS  |
+---------------------------------------------------------------------------------+
```

### The Inherent Duality
- The **Stack** models **nested hierarachy**. Every time an operation opens a scope, calls a subroutine, or matches a opening delimiter, the most recently opened context is the first that must be resolved.
- The **Queue** models **temporal preservation**. Requests are serviced in the exact chronological order in which they were submitted, preserving fairness and causality.

## 10.2 Memory Layouts: Fixed Contiguous Buffers vs. Circular Ring Queues

How are Stacks and Queues physically realized on modern silicon?

### 1. The Stack: Naturally Contiguous
Because insertions (`push`) and deletions (`pop`) take place at the exact same boundary (the "top"), a stack maps with zero friction to a contiguous flat dynamic array (`std::vector` or fixed array).
- `push(x)`: Append to index `top++`.
- `pop()`: Decrement index `--top`.
- Both operations are strictly $\mathcal{O}(1)$ with optimal cache line locality.

### 2. The Queue: The Pitfall of Naive Arrays
If an engineer attempts to implement a Queue using a naive dynamic array:
- `enqueue(x)` appends to the back ($\mathcal{O}(1)$).
- `dequeue()` removes from index 0, which requires shifting all remaining $N-1$ elements to the left, taking **$\Theta(N)$ time per removal**!
- In Python, using `list.pop(0)` turns an $N$-element queue workload into an $\mathcal{O}(N^2)$ disaster.

### 3. The Circular Ring Buffer: The Production Standard
To achieve true $\mathcal{O}(1)$ worst-case time for both enqueue and dequeue without heap fragmentation, systems engineers use a **Circular Ring Buffer**:

```
Fixed Array Buffer of Capacity C = 8:
Indices: [ 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 ]
                 ^           ^
               head        tail

State:
- head: index of oldest element (dequeue source)
- tail: index of next free slot (enqueue destination)
- count: active elements in buffer

Pointer Advances:
head = (head + 1) % C
tail = (tail + 1) % C
```

When `C` is chosen as a power of 2 ($C = 2^k$), the expensive modulo instruction (`% C`) is replaced by an ultra-fast bitwise AND:
$$\text{index} = (\text{index} + 1) \ \& \ (C - 1)$$

## 10.3 Worked Problem: STACK-0001 — Valid Parentheses String Parsing and LIFO Invariants

We now apply the **Mandatory 20-Step Problem Solving Sequence** to analyze, prove, implement, and verify the canonical LIFO validation problem: **Multi-Delimiter Syntax Parsing and Stack Invariants**.

---

### Step 1: Real-World Motivation
Every compiler frontend (e.g., Clang, GCC, Python bytecode parser), JSON serializer, and XML/HTML document validator must verify the structural syntax of incoming code. If code contains unbalanced or mismatched delimiters (e.g., `[(])`), compilation must halt immediately with an informative parse error before attempting AST construction.

In mission-critical embedded telemetry parsing, the validator must inspect multi-megabyte JSON payloads in a single streaming pass while detecting syntax corruptions in $\mathcal{O}(N)$ time.

### Step 2: Problem Identification
Given a string containing bracket characters, determine whether the input string has valid matching and correctly nested delimiters.

### Step 3: Formal Problem Statement
Let $S = [s_0, s_1, \dots, s_{n-1}]$ be a string composed solely of the bracket characters:
$$\Sigma = \{ '(', ')', '[', ']', '\{', '\}' \}$$

The string $S$ is **Valid** if and only if it can be generated by the following Context-Free Grammar (CFG):
$$E \to \epsilon \mid (E) \mid [E] \mid \{E\} \mid EE$$

Informally:
1. Every open bracket must be closed by the exact same type of closing bracket.
2. Open brackets must be closed in the correct Last-In, First-Out (LIFO) order.
3. Every closing bracket must have a preceding, unclosed matching open bracket.

#### Constraints:
- Length: $0 \le n \le 10^7$
- Characters: $s_i \in \Sigma$
- Time budget: Strictly $\mathcal{O}(n)$
- Auxiliary memory budget: $\mathcal{O}(n)$ stack space (proportional to maximum nesting depth).

### Step 4: Thinking Before Coding
1. **Odd Length Strings**: Can an odd-length string ever be valid?
   No! Every open bracket requires exactly one closing bracket. If $n$ is odd ($n \pmod 2 \ne 0$), return `False` immediately in $\mathcal{O}(1)$ time.
2. **Closing Bracket First**: If the first character is a closing bracket (e.g., `")("`), there is no preceding open bracket to match it. A pop on an empty stack is an immediate syntax violation.
3. **Mismatched Interleaving**: In `[(])`, both brackets have matching pairs, but they are improperly interleaved. A simple counter for each bracket type *cannot* detect this error; an ordered LIFO stack is mandatory!

### Step 5: First-Principles Reasoning (Why Counters Fail)
Suppose you try to count brackets:
- Increment `count_paren` on `(`, decrement on `)`.
- Increment `count_bracket` on `[`, decrement on `]`.

On input `"([)]"`:
- All counts return to 0 at the end.
- The counter algorithm incorrectly outputs `True`!
- **Why it failed**: Counters lose **temporal nesting order**. The open square bracket `[` was opened *after* `(`, which mathematically requires that `[` must be closed *before* `)` can close. A Stack preserves this exact temporal hierarchy.

### Step 6: Brute-Force Implementation (The Replacement Oracle)

```python
# Reference Baseline: Repeatedly eliminate adjacent matching pairs (O(N^2) Time)
def is_valid_parentheses_oracle(s: str) -> bool:
    if len(s) % 2 != 0:
        return False
    prev_len = -1
    while len(s) != prev_len:
        prev_len = len(s)
        s = s.replace("()", "").replace("[]", "").replace("{}", "")
    return len(s) == 0
```

### Step 7: Bottleneck Analysis
- The baseline oracle repeatedly searches for `"()"`, `"[]"`, `"{}"` and deletes them.
- In worst-case deeply nested inputs (e.g., $10^5$ opening brackets followed by $10^5$ closing brackets: `"((((...))))"`):
  - Each `replace` scans the remaining string of length $\approx N$.
  - It takes $N/2$ iterations.
  - Total time: $\Theta(N^2)$.
- For $N = 10^6$, $\Theta(N^2)$ requires over 10 minutes.
- The stack-based approach processes each character exactly once, achieving true $\Theta(N)$ linear time.

### Step 8: Candidate Solution Comparison

| Strategy | Time Complexity | Auxiliary Space | Viable for $N = 10^7$? | Notes |
| :--- | :--- | :--- | :--- | :--- |
| **String Substring Replace** | $\Theta(N^2)$ | $\Theta(N)$ | Impossible | Repeatedly re-allocates strings; quadratic |
| **Independent Counters** | $\Theta(N)$ | $\mathcal{O}(1)$ | No | **Incorrect!** Fails to detect interleaved errors |
| **LIFO Parser Stack** | $\Theta(N)$ | $\mathcal{O}(\text{depth})$ | **Optimal** | Single pass; strictly correct; minimal constants |

### Step 9: Derivation of the LIFO Parsing Algorithm
1. Check odd parity: if $n \pmod 2 \ne 0$, return `False`.
2. Initialize an empty stack of characters.
3. For each character $c$ in string $S$:
   - If $c$ is an opening bracket (`(`, `[`, `{`): push its corresponding *closing* bracket onto the stack!
     *(Engineering Tip: Pushing the expected closing bracket avoids switch-case lookups during the pop step!)*
   - Else if $c$ is a closing bracket:
     - If stack is empty (closing bracket with no matching open): return `False`.
     - Pop `expected = stack.pop()`. If `c != expected`: return `False`.
4. After inspecting all characters:
   - If stack is empty: return `True` (all brackets properly matched).
   - If stack is not empty: return `False` (unclosed opening brackets remain).

### Step 10: Correctness Proof via Stack Invariant

#### Stack Invariant:
At step $i$ (after processing prefix $S[0 \dots i-1]$):
> **Invariant**: The stack contains the sequence of expected closing delimiters, ordered from bottom to top, required to close all currently open syntactic scopes in strictly valid LIFO nesting order.

#### Base Case ($i = 0$):
The prefix is empty $\epsilon$. The stack is empty. The invariant holds.

#### Inductive Step ($i \to i+1$):
Assume the invariant holds for prefix $S[0 \dots i-1]$. Consider $c = S[i]$:
- **Case 1: $c$ is an opener**: Pushing its matching closer onto the stack establishes a new innermost scope. Any subsequent closing bracket must close this newest scope first. The invariant is maintained.
- **Case 2: $c$ is a closer**:
  - If the stack is empty, there is no open scope to close. The string cannot be generated by the grammar $E$. Returning `False` is correct.
  - If `stack.top() != c`, the current closer does not match the innermost open scope. This violates rule 1. Returning `False` is correct.
  - If `stack.top() == c`, the innermost scope is successfully closed and popped. The remaining stack represents the outer enclosing scopes, preserving the invariant.

#### Termination:
When the loop finishes, all characters have been processed.
If the stack is empty, every opened scope was closed correctly. If the stack is non-empty, at least one scope was left unclosed. The algorithm correctly returns `stack.empty()`. $\blacksquare$

### Step 11: Step-by-Step Dry Run
Input: `S = "{ [ ( ) ] }"`

| Step | Char $c$ | Action Taken | Stack State (Bottom $\to$ Top) | Valid? |
| :---: | :---: | :--- | :---: | :---: |
| Init | — | Initialize | `[]` | True |
| 1 | `'{'` | Opener $\implies$ push `'}'` | `['}']` | True |
| 2 | `'['` | Opener $\implies$ push `']'` | `['}', ']']` | True |
| 3 | `'('` | Opener $\implies$ push `')'` | `['}', ']', ')']` | True |
| 4 | `')'` | Closer $\implies$ pop `')' == ')'` | `['}', ']']` | True |
| 5 | `']'` | Closer $\implies$ pop `']' == ']'` | `['}']` | True |
| 6 | `'}'` | Closer $\implies$ pop `'}' == '}'` | `[]` (Empty) | True |

**Result**: String finished with empty stack $\implies$ `True`.

### Step 12: Full C++20 Implementation

```cpp
// solutions/cpp/STACK-0001.cpp
#include <iostream>
#include <string_view>
#include <vector>
#include <cassert>

namespace alg {

/**
 * Validates bracket syntax using a LIFO stack invariant.
 * Complexity: O(N) Time, O(N) Auxiliary Space.
 * Conforms to ISO C++20 standard using std::string_view.
 */
bool is_valid_parentheses(std::string_view s) noexcept {
    // Parity optimization: odd length strings can never be balanced
    if (s.size() % 2 != 0) {
        return false;
    }

    // Vector used as flat cache-friendly contiguous stack
    std::vector<char> stack;
    stack.reserve(s.size() / 2); // Reserve half size for expected average depth

    for (char c : s) {
        switch (c) {
            case '(':
                stack.push_back(')');
                break;
            case '[':
                stack.push_back(']');
                break;
            case '{':
                stack.push_back('}');
                break;
            case ')':
            case ']':
            case '}':
                if (stack.empty() || stack.back() != c) {
                    return false;
                }
                stack.pop_back();
                break;
            default:
                // Ignore non-bracket characters or treat as invalid per spec
                return false;
        }
    }

    return stack.empty();
}

} // namespace alg

// Differential Oracle (Repeated Replacement)
bool is_valid_parentheses_oracle(std::string s) {
    if (s.size() % 2 != 0) return false;
    size_t prev_len = 0;
    while (s.size() != prev_len) {
        prev_len = s.size();
        auto pos = s.find("()");
        if (pos != std::string::npos) s.erase(pos, 2);
        pos = s.find("[]");
        if (pos != std::string::npos) s.erase(pos, 2);
        pos = s.find("{}");
        if (pos != std::string::npos) s.erase(pos, 2);
    }
    return s.empty();
}

int main() {
    std::string_view t1 = "()[]{}";
    assert(alg::is_valid_parentheses(t1) == true);
    assert(is_valid_parentheses_oracle(std::string(t1)) == true);

    std::string_view t2 = "([)]";
    assert(alg::is_valid_parentheses(t2) == false);
    assert(is_valid_parentheses_oracle(std::string(t2)) == false);

    std::string_view t3 = "{[]}";
    assert(alg::is_valid_parentheses(t3) == true);
    assert(is_valid_parentheses_oracle(std::string(t3)) == true);

    std::string_view t4 = "]";
    assert(alg::is_valid_parentheses(t4) == false);

    std::string_view t5 = "";
    assert(alg::is_valid_parentheses(t5) == true);

    std::cout << "All C++20 assertions for STACK-0001 passed successfully." << std::endl;
    return 0;
}
```

### Step 13: Full Python Implementation

```python
# solutions/python/STACK-0001.py
def is_valid_parentheses(s: str) -> bool:
    """
    Validates bracket syntax using a LIFO stack invariant.
    Target: Python 3.12+ (O(N) Time, O(N) Auxiliary Space).
    """
    if len(s) % 2 != 0:
        return False

    stack: list[str] = []
    mapping = {'(': ')', '[': ']', '{': '}'}

    for char in s:
        if char in mapping:
            # Push expected closing bracket
            stack.append(mapping[char])
        elif not stack or stack.pop() != char:
            return False

    return len(stack) == 0


def is_valid_parentheses_oracle(s: str) -> bool:
    """Quadratic baseline oracle for differential testing."""
    if len(s) % 2 != 0:
        return False
    prev_len = -1
    while len(s) != prev_len:
        prev_len = len(s)
        s = s.replace("()", "").replace("[]", "").replace("{}", "")
    return len(s) == 0


if __name__ == "__main__":
    t1 = "()[]{}"
    assert is_valid_parentheses(t1) is True
    assert is_valid_parentheses_oracle(t1) is True

    t2 = "([)]"
    assert is_valid_parentheses(t2) is False
    assert is_valid_parentheses_oracle(t2) is False

    t3 = "{[]}"
    assert is_valid_parentheses(t3) is True

    t4 = "]"
    assert is_valid_parentheses(t4) is False

    t5 = ""
    assert is_valid_parentheses(t5) is True

    print("All Python 3 self-tests for STACK-0001 passed successfully.")
```

### Step 14: Complexity Analysis
- **Time Complexity**: $\Theta(N)$
  - Each character in the string is visited once.
  - A character is either pushed onto the stack or popped from the stack at most once.
  - Exactly $\le 2N$ total stack operations $\implies \Theta(N)$ time.
- **Space Complexity**: $\mathcal{O}(N)$ auxiliary memory
  - In the worst case (e.g., `"((((...((("`), all $N$ characters are opening brackets and pushed onto the stack.
  - For balanced inputs, space is bounded by the maximum syntactic nesting depth.

### Step 15: Edge Cases and Failure Modes
- **Empty String**: Returns `True` (vacuously valid CFG).
- **Odd Length**: Fast parity check returns `False` in $\mathcal{O}(1)$ without allocating memory.
- **Closing Bracket First**: Stack underflow checked immediately via `stack.empty()`.
- **All Openers**: String terminates, but `stack.empty()` returns `False`.

### Step 18: Further Optimization
- If the alphabet consists solely of a single bracket type (e.g., only `'('` and `')'`), the stack can be replaced by a single scalar integer `balance`: increment on `'('`, decrement on `')'`, abort if `balance < 0`, verify `balance == 0` at end. This reduces space from $\mathcal{O}(N)$ to strictly $\mathcal{O}(1)$.
